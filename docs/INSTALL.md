# ReachCommander installation index

Choose the platform guide for the machine that will run ReachCommander:

- [Ubuntu production installer](deployment/ubuntu.md) — Docker Engine deployment with a recommended loopback-bound HTTPS upstream or explicit trusted-LAN HTTP, digest-pinned updates, rollback, and safe uninstall.
- [macOS one-command installer](deployment/macos.md) — Docker Desktop deployment for Intel or Apple Silicon, with specific-folder or advanced broad-source choices.
- Windows development and source execution are documented in the [README](../README.md#local-development). Production Ubuntu remains the recommended self-hosted target.

Before enabling writes, read the [file operations and managed Trash runbook](operations.md). Back up the installer/native `/data` location for authentication and durable queue metadata. Separately back up `.reachcommander-trash` inside every writable source whose deleted items must remain recoverable; installers do not remove or include source-local Trash in ordinary uninstall backups.

ReachCommander terminates no TLS itself. Ubuntu defaults to a loopback-only HTTPS reverse-proxy upstream. Its explicit **Direct HTTP on trusted LAN** option publishes `8092` to all host interfaces and forwards to container port `8080`; transport is unencrypted even though application authentication protections remain enabled. Do not configure router forwarding or public exposure. Start with narrowly scoped read-only sources, then opt individual destinations into `readOnly: false` only after verifying host permissions and backups.

The in-app full-stack update control is supported only by an Ubuntu installer-managed deployment. Existing installations must run the new checksum-verified installer once to add `reachcommander-updater.service` and the read-only `/run/reachcommander-updater` socket mount. Automatic discovery runs at startup and every six hours, but Apply always requires administrator confirmation. Exact version pins remain pinned; Windows, macOS, and manual container installations display a safe unsupported state.

Current Ubuntu installer-managed deployments also enable **Add source** for one existing absolute Ubuntu host folder. Choose a specific child directory such as `/srv/family-media`. Every parent must be root-owned and not group- or world-writable; the runtime-owned leaf may remain writable. A normal `/home/user/...` path fails this ancestry check, so use a narrow root-controlled stable mount under `/srv` instead of changing home-directory ownership or permissions. Verify read/traverse/write access as the configured runtime UID/GID, and keep the read-only by default policy unless controlled writes are necessary. Read/write requires an explicit read/write confirmation because ReachCommander can change or delete files in that host folder. The add transaction revalidates every configured source before any change. The × on each source chip removes only the selected mapping after confirmation; host files are never deleted and at least one mapping is retained. A successful add or remove transaction restarts only the ReachCommander application container; the blocking UI reconnects automatically and refreshes both source selectors. The container receives only `/run/reachcommander-updater` and never mounts `/var/run/docker.sock`.

The production image includes pinned FFmpeg/FFprobe support for the **Synchronize subtitles** workspace. MP4, MKV, and AVI video can load a same-name SRT; a read-only source can preview offsets, while a writable source can preserve `movie.srt` as `movie_original.srt` (then `movie_original (2).srt`) and publish the corrected SRT. The video is never modified. Temporary HLS state stays in the existing writable `/data/media-previews` tree—no additional host mount is required—and is bounded to 90 minutes and 8 GiB per transcode. SRT parsing is limited to 4 MiB and 20,000 cues. On a native development host, verify `ffmpeg -version` and `ffprobe -version`; normal Docker installs already contain both binaries.

Existing, older installations need to rerun the latest checksum-verified installer once because an image-only update cannot replace the root-owned helper. Clean installations include the compatible source helper immediately. Use `sudo reachcommander doctor` and the Ubuntu guide's support diagnostics when a transaction times out or rolls back; `sudo reachcommander source add` is the advanced CLI fallback when the browser is unavailable.
