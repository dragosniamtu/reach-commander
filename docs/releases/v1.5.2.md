# ReachCommander v1.5.2

Restore reliable update checks after the host updater restarts and allow existing text conversion state during installer upgrades.

## Fixes

- Preserve the updater socket directory across service restart and stop/start, keeping running application containers connected.
- Retry the configured Linux helper when it becomes available after application startup, without requiring another application restart.
- Accept, preserve, back up, and safely remove the exact text encoding staging records created by ReachCommander. Existing installations no longer fail validation because this legitimate directory is present.
- Apply private directory permissions to new text encoding registry directories and normalize existing registry permissions during installer refresh.
- Give text conversion status polling its own bounded request budget, so normal progress checks do not exhaust the limit for preview, execute, or cancel commands.

## Upgrading Ubuntu installations

Follow the [checksum-verified installation instructions](https://github.com/dragosniamtu/reach-commander/blob/v1.5.2/docs/deployment/ubuntu.md) and rerun the v1.5.2 installer once. This updates the root-owned systemd unit and management tools while preserving application data, configured sources, and optional subtitle models. An application-only update cannot install the host-side fix.

For an older installation already showing **Unknown**, wait for active file operations to finish, then run:

```bash
sudo docker compose --project-directory /opt/reachcommander up -d --force-recreate reachcommander
```

Reload the page and retry the update check, then complete the installer refresh. Run `sudo reachcommander doctor` afterward.

CPU subtitle generation and its optional worker remain available as introduced in v1.5.0.

The v1.5.1 release was withheld after verification exposed the polling limit issue; v1.5.2 includes the complete patch.
